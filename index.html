二、我们和第三方处理的信息

1. 游戏自身与联机功能

按当前游戏运行代码核查，游戏没有玩家注册/登录、姓名或手机号档案、位置/通讯录采集、广告以外的分析或崩溃上报实现；没有实现将玩家档案或对局进度写入本地存档的功能。对局状态仅在本次运行期间由游戏处理。该代码核查不涵盖 Android 系统、TapADN SDK 或 TapTap 平台可能进行的独立处理。

真人对战的正式玩法仍为玩家主机权威的局域网直连。玩家可在大厅输入房主的 IP 地址和端口；主客机通过 ENet/UDP 交换玩家席位、游戏指令及单位/建筑/资源等对局状态。因此，建立网络连接会使用连接端的网络地址，房主和访客会在直连中处理建立连接所需的对端网络信息。当前游戏代码没有将这些网络地址写入玩家档案或本地日志。离线对局状态也只在运行期间存在。

TapTap Battle V4 云联机入口（Android 试验功能）。当前 Android 包内包含 TapTap Battle SDK 4.11.0 和隔离的云连接入口；它依赖 TapTap 登录。玩家在进入该入口并通过同意、登录和合规门禁后，SDK/云服务可能处理连接返回的云玩家 ID、在线/离线状态、房间 ID、房主 ID、房间名称和类型、玩家列表、房间/玩家自定义属性、创建/加入/离开事件、定向或广播自定义消息以及帧同步输入/回调。当前大厅云房间入口仅使用固定 1v1 房间类型、空房间名/属性和默认玩家状态；正式游戏流程尚未发送自定义消息或帧同步输入，也未把云数据接入正式 MatchSession。不应在未来配置的自定义字段或消息中放入姓名、手机号、证件号、精确位置或其他无关个人信息。该入口目前只用于 Android 云房间/传输试验；正式对局仍使用局域网 ENet，具体云服务处理以 TapTap 现行公开政策和平台流程为准。

玩家选择激励视频后，广告完成回调和奖励申请会在本局设备间传递随机 claim ID、观看秒数和已有的玩家席位信息。claim ID 用于房主阻止同一个申请重复发奖；奖励申请通过本局现有 ENet/UDP 联机连接发送，不会因此请求独立的公网奖励验证服务。该设计由房主维持本局游戏状态权威，但不能独立证明访客设备实际播放了广告；奖励只适用于休闲游戏，不用于付费、提现或竞技排名。

2. TapADN SDK

为请求、播放和衡量激励视频，并进行广告反作弊、归因和服务稳定性分析，我们通过集成的 TapADN SDK（Android 5.3.2.0），向 SDK 提供方 上海艾得蒽数字科技有限公司及其关联方 提供 SDK 正常运行所需的应用环境。SDK 由其在设备端自行采集信息；具体处理以实际 SDK 版本和 TapADN 后台功能配置为准。

TapADN 公开资料列出的 Android 必要信息包括：设备品牌、型号、系统版本、屏幕密度和分辨率、设备语言与时区、CPU 信息、可用存储空间、OAID；网络信息（IP 地址、Wi‑Fi 状态和信号强度）；应用包名、版本、运行中的进程及前后台状态；广告展示、点击和转化等交互数据；崩溃及性能数据。用途包括广告投放、广告效果监测/归因、反作弊及 SDK 稳定性分析。TapADN 可能按其政策与关联方、广告主、代理商、广告监测等合作方共享实现广告投放和效果分析所需的信息；详情见其隐私政策。

TapADN 公开资料还列出可选信息或权限，例如 IMEI/Android ID/AAID/VAID、设备硬件序列号（Serial）、位置、软件列表、传感器、设备 MAC、SSID/BSSID 和外部存储。当前游戏的 11 个自定义采集开关均传入关闭值，不请求位置、电话状态、软件列表、传感器或外部存储权限；其中 TapADN Android SDK 文档称 isCanUsePhoneState=false 会阻止读取或使用缓存的 Serial，isCanUseOaid=false 会关闭 SDK 自行获取 OAID，isCanUseWifiState=false 会关闭 Wi‑Fi 状态访问并限制 BSSID/SSID；广告个性化设置始终为限制状态，不提供个性化广告启用入口。但 TapADN 当前公开隐私政策把 OAID 和 Wi‑Fi 状态/信号列为必选信息，而本项目明确关闭相应 SDK 开关。实际 SDK 行为和广告填充以最终 Android 设备、TapADN 后台配置及 TapADN 最新公开政策为准；本政策保留其公开政策列出的必要字段披露，不因本项目关闭部分可选开关而缩减告知范围。 限制个性化广告不等于停止广告投放或停止 SDK 为基础广告服务处理其必要信息。

TapADN SDK 提供方的主体名称、信息字段、目的及隐私政策以 TapADN SDK 隐私政策 和 TapADN SDK 合规使用说明 为准。TapADN 声明其在境内运营中收集的信息存储在中国境内，并按提供服务所需期间保存。当前游戏奖励流程不使用独立公网奖励验证服务。

3. TapTap 登录、合规认证与 Battle V4 SDK

应用接入 TapSDK Android v4.11.0 的核心、登录和合规模块。玩家同意本游戏隐私政策后才初始化 SDK。游戏仅请求 basic_info 授权，获取游戏内 openId / unionId 用于 TapTap 合规认证，不请求昵称、头像或好友信息。TapTap 合规认证及登录可能处理系统版本、设备型号、CPU、网络类型、Android ID、设备内存、网络连接状态等官方政策所列信息，用于 TapTap 服务、设备兼容和故障排查；TapTap 作为平台服务提供方按其自身隐私政策处理。SDK 还将根据用户授权提供年龄段结果供本机规则判断；本游戏当前不保存年龄段，也不通过游戏对局网络发送账号标识或年龄。

数据类别、存储期限、平台侧留存/共享方式及未成年人监护人权利办理入口，以实际 TapSDK v4.11.0 文档、TapTap 隐私政策和最终构建/真机核验结果为准。本应用已完成主菜单全局同意与登录/合规门控，但尚未完成 Android 设备回调和平台测试证明，本段按当前接入范围说明平台 SDK 的处理边界。

TapTap Battle V4 的云房间与传输服务由 TapTap SDK/平台提供。云玩家 ID、IP 或连接网络信息、在线状态、房间与玩家元数据、自定义属性、自定义消息和帧同步输入等，按 TapTap 现行公开隐私政策和平台流程处理；具体存储地域、期限、共享/委托、删除导出及未成年人权利办理方式以 TapTap 最新公开说明为准。

4. 本局奖励处理

TapADN 客户端 onRewardVerify 接受后，观看设备通过本局 ENet/UDP 连接向玩家房主提交一个随机 claim ID 和客户端根据广告展示到视频完成间隔计出的秒数。房主检查申请是否来自对局中的对应席位、对局是否仍在进行、秒数是否有效并封顶、claim ID 是否已用过；通过后由房主决定数量和 Gold/Wood/Food 资源类型，并在权威对局状态中写入及同步结果。claim ID、观看秒数和奖励结果只在本局联机消息/运行状态中处理，不写入独立的公网奖励数据库。

对局房主本身是玩家设备，不是独立运营方服务器。房主可维护资源状态权威及重复申请检查，但无法独立认证访客设备收到的广告 SDK 回调或客户端报告的秒数。因此，该机制只适用于休闲奖励，不应描述为防作弊或独立服务端认证。游戏不据此处理付费、提现或竞技排名。

5. 对局网络

真人对战采用同一局域网内的 ENet/UDP 直连，不使用本项目自建的互联网匹配服务器。玩家需要输入房主 IPv4 地址和端口；主客机会交换对局指令与状态快照。由此产生的连接地址用于建立本次连接；游戏业务代码不保存该地址。跨互联网的连接能力目前不支持。若最终平台网络实现与此不同，发布前须按目标设备重新核对并修订。

三、处理目的、方式和保存期限

游戏自身的联机状态仅在对局运行期间处理，当前游戏代码不建立本地玩家档案或对局存档。TapTap Battle V4 云房间数据由 SDK/云服务按其接口处理；本项目未建立独立 Battle 数据库；平台侧云玩家 ID、房间/玩家状态、消息/帧输入、连接日志和关联设备信息的保存、删除及权利办理按 TapTap 最新公开政策执行。我们仅在玩家主动选择观看激励视频并同意后，为广告请求/播放、广告效果衡量以及本局奖励处理使用上述信息。奖励 claim 和对局资源状态通过本局 ENet/UDP 连接由房主处理并随本局状态保留。TapADN 的保存规则见其政策；本项目不将 claim 或奖励记录发送到独立公网奖励验证服务。
